ΥΠΟΧΡΕΩΤΙΚΗ ΔΙΑΔΙΚΑΣΙΑ ΕΓΚΡΙΣΗΣ

1. Read-only inspect

Πριν τροποποιήσεις οτιδήποτε, κάνε πλήρη read-only έλεγχο του project:

* framework, δομή και Git status
* υπάρχον blog/CMS, content model και publishing workflow
* router, routes, sitemap και media manager
* layouts, templates, components και design system
* metadata, schema και internal linking patterns
* διαθέσιμα tests, build, lint και validation scripts
* τυχόν uncommitted ή άσχετες αλλαγές

Μην δημιουργήσεις ή τροποποιήσεις αρχεία, CMS records, media ή περιεχόμενο σε αυτή τη φάση.

2. Σχέδιο αλλαγών

Σταμάτησε και παρουσίασε αναλυτικό σχέδιο που να περιλαμβάνει:

* αρχιτεκτονική και υπάρχοντα components που θα επαναχρησιμοποιηθούν
* αρχεία, CMS records και media που ενδέχεται να δημιουργηθούν ή τροποποιηθούν
* προτεινόμενο route και slug, αφού ελεγχθούν για duplicates
* metadata, structured data, internal links και sitemap
* backup ή Git checkpoint
* tests και validation checks
* πιθανούς κινδύνους ή στοιχεία που απαιτούν επιβεβαίωση
* εκτίμηση του τελικού diff και επιβεβαίωση ότι δεν περιλαμβάνει άσχετες αλλαγές

Μην προχωρήσεις χωρίς ρητή έγκριση. Αν χρειαστεί αλλαγή εκτός εγκεκριμένου σχεδίου, σταμάτησε και ζήτησε νέα έγκριση.

ΑΣΦΑΛΕΙΑ ΚΑΙ ΠΡΟΣΤΑΣΙΑ ΥΠΑΡΧΟΝΤΟΣ WEBSITE

Μετά την έγκριση:

* Δημιούργησε Git checkpoint ή ασφαλές backup χωρίς να συμπεριλάβεις άσχετες αλλαγές.
* Χρησιμοποίησε αποκλειστικά το υπάρχον CMS, blog architecture, content model, schema, metadata, media workflow και publishing process.
* Μην δημιουργήσεις δεύτερο CMS, blog system, schema mechanism ή παράλληλο workflow.
* Μην αλλάξεις υπάρχουσες σελίδες, URLs, routes, navigation, header, footer, CSS, global styles, components, forms, performance settings ή λειτουργίες.
* Μην δημιουργήσεις duplicate route, slug, content ή sitemap entry.
* Μην επινοήσεις authors, prices, services, testimonials, ratings, certifications, URLs, company claims ή schema στοιχεία.
* Πρόσθεσε μόνο ό,τι απαιτείται για το νέο άρθρο και ακολούθησε το υπάρχον design, typography, spacing και responsive behavior.

ΠΕΡΙΕΧΟΜΕΝΟ ΑΡΘΡΟΥ

Δημιούργησε original, factual, people-first και authoritative άρθρο περίπου 2.000–3.000 λέξεων, μόνο εφόσον το μήκος εξυπηρετεί ουσιαστικά το θέμα.

Το άρθρο πρέπει να:

* απαντά άμεσα στην ερώτηση «Μπορώ να πάρω δωρεάν ιστοσελίδα;»
* εξηγεί τι σημαίνει πραγματικά «δωρεάν ιστοσελίδα»
* αναλύει domain, hosting, SSL, email, maintenance, security, backups, SEO και support
* συγκρίνει δωρεάν και επαγγελματικές λύσεις χωρίς απόλυτες κρίσεις
* εξηγεί πότε αξίζει δωρεάν λύση και πότε χρειάζεται επαγγελματική ιστοσελίδα
* εξηγεί ότι website δεν σημαίνει αυτόματα traffic ή πελάτες
* βοηθά τον αναγνώστη να πάρει τεκμηριωμένη επιχειρηματική απόφαση
* οδηγεί φυσικά στις σχετικές υπηρεσίες της Codehouse, χωρίς μη επαληθευμένους ισχυρισμούς

Χρησιμοποίησε ένα H1, σωστή H2/H3 ιεραρχία, σύντομες παραγράφους, bullets, πίνακες, checklists και FAQ.

Χρησιμοποίησε φυσικά σχετικά terms όπως δωρεάν website, δωρεάν ιστοσελίδα για επιχείρηση, κατασκευή ιστοσελίδας, κόστος ιστοσελίδας, επαγγελματική ιστοσελίδα, SEO, hosting, domain, SSL και συντήρηση.

Για SEO/GEO:

* δώσε άμεσες απαντήσεις νωρίς
* χρησιμοποίησε descriptive headings, bullets, tables και σαφείς ορισμούς
* κράτησε σύντομες παραγράφους

* μην παρουσιάσεις μη επαληθευμένες πληροφορίες ως γεγονότα
* απάντησε καθαρά σε ερωτήσεις όπως «Αξίζει δωρεάν ιστοσελίδα;», «Τι πληρώνω;», «Χρειάζομαι domain, hosting ή SEO;»

METADATA ΚΑΙ STRUCTURED DATA

Χρησιμοποίησε τον υπάρχοντα μηχανισμό του project για:

* μοναδικό SEO title έως περίπου 60 χαρακτήρες
* meta description περίπου 150–160 χαρακτήρες
* SEO-friendly slug, ενδεικτικά /blog/dorean-istoselida
* ένα H1 με τον τίτλο του άρθρου
* canonical URL
* Open Graph και Twitter/X metadata
* robots directives
* breadcrumbs
* Article ή BlogPosting Schema
* BreadcrumbList Schema
* FAQPage Schema μόνο εφόσον υποστηρίζεται και είναι συμβατό με τις τρέχουσες οδηγίες

Μην δημιουργήσεις fake authors, reviews, ratings ή organization data.

MEDIA, UX ΚΑΙ PERFORMANCE
